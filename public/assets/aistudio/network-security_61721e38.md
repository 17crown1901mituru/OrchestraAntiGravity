# Network security guidelines &nbsp;|&nbsp; Security &nbsp;|&nbsp; Google Cloud Documentation
URL: https://docs.cloud.google.com/docs/security/gcmvsp/network-security

The following guidelines for the minimum viable security platform align with the network security pillar.

Basic level guidelines
----------------------

Implement the following network security guidelines first.

<table><tbody><tr><th>Item</th><td><h3 id="block-default-network-creation" data-text="Block default network creation" tabindex="-1">Block default network creation</h3></td></tr><tr><th>Description</th><td><div><p>The <code translate="no" dir="ltr">compute.skipDefaultNetworkCreation</code> boolean constraint skips the creation of the default network and related resources when creating Google Cloud projects.</p><p>The default network is an auto-mode Virtual Private Cloud (VPC) network with pre-populated IPv4 firewall rules to allow internal communication paths. After you implemented the basic guidelines, implement the following network security guidelines.

<table><tbody><tr><th>Item</th><td><h3 id="use-cloud-armor-policies" data-text="Use Cloud Armor policies" tabindex="-1">Use Cloud Armor policies</h3></td></tr><tr><th>Description</th><td><p>For applications that are exposed behind Cloud Load Balancing, use Google Cloud Armor default policies or configure your own policies to add Layer 3 to Layer 7 network protection for externally-facing applications or services. Cloud Armor security policies help protect your application by providing Layer 7 filtering. These policies also review incoming requests for common web attacks or other Layer 7 attributes to potentially block traffic before the traffic reaches your load-balanced backend services or backend buckets. Each security policy is made up of a set of rules that include attributes from Layer 3 through Layer 7.</p></td></tr><tr><th>Related information</th><td><ul><li><a href="https://docs.cloud.google.com/armor/docs/cloud-armor-overview">Cloud Armor overview</a></li></ul></td></tr><tr><th>Item ID</th><td>MVSP-CO-1.49</td></tr><tr><th>Mapping</th><td><p>Related NIST-800-53 controls:</p><ul><li>SC-7</li></ul><p>Related CRI profile controls:</p><ul><li>PR.AC-3.1</li></ul><p>Compliance Manager control:</p><ul><li><a href="https://docs.cloud.google.com/security-command-center/docs/compliance-manager-cloud-controls#define-security-policy-mitigate-ddos-events">Define a Security Policy to Mitigate for DDoS Events</a></li></ul></td></tr></tbody></table>

<table><tbody><tr><th>Item</th><td><h3 id="restrict-outbound-traffic" data-text="Restrict outbound traffic" tabindex="-1">Restrict outbound traffic</h3></td></tr><tr><th>Description</th><td><div><p>Limit access to external sources because by default, all access is allowed out. Set specific firewall rules for intended patterns of traffic needing to egress.</p><p>By default, systems are often allowed to make outbound connections to the internet, which can be deemed a security risk. A deny-by-default policy blocks outbound traffic and requires specific rules to be created for only the known, necessary destinations.</p></div></td></tr><tr><th>Related information</th><td><ul><li><a href="https://docs.cloud.google.com/firewall/docs/firewalls">VPC firewall rules</a></li></ul></td></tr><tr><th>Item ID</th><td>MVSP-CO-1.50</td></tr><tr><th>Mapping</th><td><p>Related NIST-800-53 controls:</p><ul><li>SC-7</li></ul><p>Related CRI profile controls:</p><ul><li>PR.AC-3.1</li></ul><p>Compliance Manager control:</p><ul><li><a href="https://docs.cloud.google.com/security-command-center/docs/compliance-manager-cloud-controls#enforce-deny-all-egress-firewall-policy">Enforce Deny All Egress Firewall Rule</a></li></ul></td></tr></tbody></table>

<table><tbody><tr><th>Item</th><td><h3 id="limit-inbound-access-to-ssh-and-rdp-ports" data-text="Limit inbound access to SSH and RDP ports" tabindex="-1">Limit inbound access to SSH and RDP ports</h3></td></tr><tr><th>Description</th><td><div><p>Where possible, restrict inbound access to specific resources and resource ranges only.
